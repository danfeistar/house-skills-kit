# 二手房交易全流程与风险（resale-transaction-sop）

## 一句话定位

把"一套二手房从看中到拿到钥匙"拆成 **12 个可执行节点**，每个节点写清三件事：谁做、要什么材料、卡住怎么补救。
产出是**一份可打印的交易时间轴 + 一张风险排查表**，不是流程科普。

不覆盖：房源开发与委托（`broker-listing-sop`）、客户匹配与议价（`broker-client-deal-sop`）、租赁作业（`broker-lease-sop`）、
新房交易（`newhome.py`）。本技能只负责"已经谈成、要把它安全地办完"这一段。

## 适用角色

- 二手经纪机构 / 门店：新经纪人上手的作业手册，店长盯节点管控
- 独立经纪人 / 合作单：判断这一单的卡点在哪、这单该不该接
- 买方 / 卖方（自助交易）：每一步该准备什么、哪些钱不该先付
- 房产自媒体 / 顾问：讲清"这单为什么卡住了"

## 八类触发场景

1. 客户第一次买二手，问"要多久、先干什么、钱什么时候付"
2. 卖家的房子还有按揭没结清，问"赎楼谁出钱、能不能先过户"
3. 买方问"定金交了能退吗"、"合同签了卖家反悔怎么办"
4. 网签之后贷款批不下来，三方僵住
5. 税费谁承担、满二满五怎么算、能不能把成交价做低一点
6. 过户前发现房子被查封、有共有人没签字、租客没搬
7. 交房时户口没迁走、水电欠费、物业费谁结、家具家电对不上
8. 客户想跳过中介自助交易，问风险在哪、怎么保护自己

## 五条核心认知

1. **二手交易的风险九成不在价格，在权属和履约**。价格谈贵 3% 是少赚，权属有瑕疵是本金全没。查档永远是第一步，不是签完合同再补。
2. **顺序决定钱的安全**：查档 → 定金 → 网签与资金监管 → 贷款审批 → 缴税过户 → 放款交房。任何一步把后面的动作提前（例如没进监管就付大额首付），风险就从"可追"变成"难追"。
3. **定金和订金不是一个东西**。只有写明"定金"且实际交付，才适用定金罚则；写"订金 / 意向金 / 认筹金"的，法律上不产生双倍返还效果。这是客户问得最多的一条，必须一次说准。
4. **贷款批不批，是全程最不可控的变量**。评估价低于成交价、房龄超限、收入流水不足、征信有瑕疵，任何一条都能让交易停摆。合同里必须写明"贷款不批怎么办"，否则默认买方违约。
5. **口头承诺全部作废**。家具家电、户口迁出、租客清退、维修责任、交房时间——没写进合同或补充条款、没有对应违约责任的，等于没有。

## 必问信息（不齐就先问，别猜）

| 字段 | 为什么要问 |
|---|---|
| 产权证号 / 不动产权证与登记时间 | 决定是否满二满五、能否交易、从哪查档 |
| 房屋性质：商品房 / 房改房 / 经适房 / 回迁房 / 公寓 / 商业 | 性质直接决定税费档、限售期、能不能贷款、贷款年限 |
| 是否存在抵押（按揭余额、抵押给谁） | 有抵押必须先赎楼，赎楼资金谁出、走不走担保，是最大的卡点 |
| 是否存在查封 / 异议登记 / 居住权登记 | 这三项任一项在，交易无法完成，签约前必须查清 |
| 共有人名单（含夫妻、继承、代持） | 少一个共有人签字，合同就可能无效或无法过户 |
| 是否存在租赁、租约还剩多久 | 买卖不破租赁，带租约的房子过户后租客可以不搬 |
| 卖方户口是否在该房、是否有学位占用 | 户口不迁是交房后最常见的纠纷；学位占用影响买方的实际用途 |
| 买方购房资格与贷款资质（本地套数、房贷记录、征信、流水） | 资格与资质是"能不能买"，不是"愿不愿意买" |
| 成交价、评估价预期、首付来源与比例 | 评估价低于成交价时，差额必须现金补，很多单子死在这 |
| 税费由谁承担、是否各自承担 | 口头"包税"是最常见的扯皮源，必须写进合同 |
| 交房时间、随房交付的家具家电清单 | 交房争议 80% 来自"当时说的是不是含这个" |

## 知识库与数据来源

- 交易税费与全成本：`skills/calc-toolkit/tax.py`（契税 / 增值税 / 个税 / 各项费用，逐项标来源与规则版本）
- 定金罚则与违约金：`skills/calc-toolkit/deposit.py`（`--mode penalty` 定金罚则，`--mode late` 逾期违约金）
- 房龄与贷款年限：`skills/calc-toolkit/loanterm.py`（房龄线 / 年龄线 / 公积金线三线取短）
- 首套二套认定：`skills/calc-toolkit/status.py`（商贷 / 公积金 / 契税三套口径分别判定）
- 公积金额度：`skills/calc-toolkit/fund.py`；月供与组合贷：`skills/calc-toolkit/mortgage.py`
- 面积误差补退：`skills/calc-toolkit/area_error.py`（3% 红线法定兜底口径）
- 中介费与分佣：`skills/calc-toolkit/commission.py`
- 政策口径（限购、限售年限、税费优惠、公积金、网签与资金监管要求）：**一律按当地当期公告与经办部门口径现查**，本技能不含任何城市的具体数字
- 不可采信：卖方口述的"满五唯一"、同行口头报的税费金额、三年前的流程文章、朋友圈截图里的政策

## 目标读者

- **执行层**：经纪人、门店店长、交易管家——按 Part 逐节点执行
- **决策层**：机构负责人——看 Part 1 与 Part 7，抓节点管控与风险兜底
- **买卖双方**：看 Part 3、Part 6，知道哪些钱不该先付、哪些条款必须写
- **对外版要删什么**：内部议价底牌、同行对比话术、"这个单子我判断能压多少"这类内部判断一律不进客户版

## 写作风格

- 结论先行：先给"这一步能不能做 / 现在该谁动"，再解释原因
- 一律用动作句，不用形容词："过户前必须完成抵押注销"而不是"要注意抵押问题"
- 不给概率、不给"大概几天"，时间一律写成"取决于 X，通常由 X 决定"，并注明以当地经办部门为准
- 涉及法律责任只写规则与后果，不给"法院一定判你赢"这类结论
- 每个结论必须能追溯到：合同条款、登记簿记载、经办部门口径三者之一

## 输出格式

- **交易时间轴（首选交付）**：12 节点 × 4 列（节点 / 谁做 / 要什么材料 / 卡点与补救），一页 A4
- **风险排查表**：12 项权属与履约检查，逐项标"已核 / 待核 / 有风险"，含核查渠道
- **费用清单**：买方费用、卖方费用分列，每项由 `tax.py` 出数并标取数日期
- **合同补充条款建议**：针对本案的 5~8 条（贷款不批、户口迁出、租客清退、家具家电、逾期交房）
- 所有交付物必须含：核查日期、政策核对日期、经办口径来源（哪个部门 / 哪份公告）

## 数据时间戳

- 税费与政策：标注公告名称与生效日，**超过 30 天必须复核**（税率与优惠档调整频繁）
- 房贷利率与贷款年限口径：按经办行当期口径，标注沟通日期与经办行
- 权属与查封：查档结果**以过户当日的最新登记簿为准**，签约前查过一次不等于过户时仍然干净
- 房源价格与评估价参考：超过 30 天重取
- 所有交付物必须写"核查日期"，禁止用三个月前的查档结果支撑今天的付款决定

## 与其他技能的关系

- 还没找到房源、要签委托 → `broker-listing-sop`
- 还在谈价、客户犹豫、要比价 → `broker-client-deal-sop`
- 要算税费全成本、月供、可贷额度 → `calc-toolkit`（`tax.py` / `mortgage.py` / `fund.py` / `status.py`）
- 交房验收环节的专业验收清单 → `handover-inspection-advisor`
- 租房（含过户后继续出租）→ `broker-lease-sop`
- 所有金额一律走命令测算，不口算、不给"大概"
