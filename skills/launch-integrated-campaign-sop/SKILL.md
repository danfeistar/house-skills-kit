# 节点开盘整合营销 SOP（标准作业程序）· launch-integrated-campaign-sop

**一句话**：把开盘从单日活动升级为一场可倒排、可协同、可校验、可复盘的营销战役；本技能管策略整合，现场细节交给 `sales-opening-sop`。

**适用角色**：营销负责人、策划、渠道、案场、工程/客服、内容、活动供应商、财务和项目负责人。

## 使用规则

1. 先锁定节点目标、真实房源、批准价格和承载能力，再编排营销动作。
2. 每个动作必须对应目标、客群、来源、负责人、预算和回读指标。
3. 对外口径以当前审批版本为准；未确认的房源、价格、优惠、工程和配套不进入宣传。
4. 传播热度不能替代客户自主决策，不用虚假稀缺、虚构排队或谎报去化制造压力。
5. 本技能负责跨团队整合和战役节奏；开盘日三区动线、叫号、销控和应急执行引用 `sales-opening-sop`。

## 核心流程

```text
节点确认 → 目标与房源锁定 → 客群/渠道盘点 → 战役主题
→ 倒排节奏 → 资源与预算 → 内容/活动/物料/渠道联动
→ 认筹收口与意向冻结 → 全员演练 → 开盘执行
→ 盘后转化 → 战役复盘
```

### 版本闸口

```text
事实来源确认 → 负责人审核 → 统一版本编号
→ 全员培训/签收 → 旧版回收 → 开盘前抽查
```

价格、房源、优惠和选房规则任何一个版本未锁定，战役不得进入对外扩量阶段。

## 五、整合传播与承接

### 传播链

```text
真实节点信息 → 客群分层 → 内容/活动/渠道触达
→ 合规报名 → 到访/咨询 → 需求记录
→ 意向房源登记 → 认筹冻结 → 开盘执行
```

每条传播都登记：来源码、目标客群、批准版本、承接人、有效期和后续动作。内容只讲已核验事实；创作工艺引用内容线技能，不在这里重复建立拍摄剪辑方法。

### 承接检查

- [ ] 报名入口和隐私授权清楚
- [ ] 到访容量和分时安排匹配
- [ ] 客户问题能转给明确负责人
- [ ] 价格、优惠和工程问题有统一答疑卡
- [ ] 认筹/选房规则已公示且不可由顾问临时改变
- [ ] 渠道、业主推荐和自然来访来源分别记录

## 六、全员演练

### 演练场景

1. 客户拿旧价格或旧优惠截图到场
2. 渠道报备与自然来访或其他渠道重复
3. 目标户型临时状态变化
4. 客户质疑选房顺序和房源余量
5. 活动超承载、系统故障或现场客诉
6. 工程、交付和质量问题被集中追问
7. 未选房客户要求解释后续安排

## 七、开盘日衔接

开盘日执行直接调用 `sales-opening-sop`：

- 开盘前：客户梳理、意向落位、房源与价格锁定
- 开盘中：签到、等候、叫号、选房、认购、签约和销控
- 突发时：现场总指挥统一决策，其他人不自行改规则
- 开盘后：未选房客户、剩余房源、数据和问题交接

本技能只检查跨线资料是否齐套，不替代现场总指挥，也不输出未批准的排号、价格和房源规则。

## 八、盘后复盘

### 24/72小时复盘

- **24小时**：核对到场、认购、未选房、渠道来源、价格版本和异常记录。
- **72小时**：分析目标达成、客群结构、动作费效、口径偏差、投诉和下一步去化。
- **7天内**：关闭版本、归档证据，形成不超过 {{5}} 条可执行改进。

| 复盘维度 | 记录内容 |
|---|---|
| 目标 | 目标值/实际值/差异原因 |
| 房源 | 目标户型去化、剩余和异常 |
| 客户 | 来源、分层、到场、选房和未成交原因 |
| 渠道 | 有效报备、到访、成交和对账差异 |
| 内容/活动 | 触达、承接、预约和实际转化 |
| 价格 | 优惠使用、审批偏差和客户敏感点 |
| 现场 | 排队、叫号、销控、签约和客诉问题 |
| 改进 | 负责人、截止时间和验收方式 |

## 合规红线

1. 不得虚构开盘日期、库存、认筹人数、成交量、排队、抢购或“最后机会”。
2. 不得在价格、房源、优惠、佣金和选房规则未审批或已变更时继续使用旧口径。
3. 不得通过关系户插队、私改顺序、虚报余量或选择性报价破坏公平规则。
4. 不得在预售、认筹、团购、付款和优惠事项上绕过公示和财务流程。
5. 不得买卖客户名单，不得诱导客户改来源，不得未经授权公开客户信息。
6. 不得隐瞒已公开的工程、质量、延期或客诉事实，不得用营销活动转移问题。
7. 发现重大事实错误、安全隐患、违规宣传或群体性争议时，先暂停相关动作并由授权负责人处理。
