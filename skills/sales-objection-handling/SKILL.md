# 客户异议处理 · sales-objection-handling

**一句话**：案场高频客户异议的三段式处理库——接（共情）→ 拆（找真实顾虑）→ 转（重构+证据+行动），每条异议配应对话术、禁语清单、分客群变通。

**适用角色**：置业顾问（日常应对）、销售经理（培训复盘）、营销策划（案口 FAQ 底稿）

**核心认知**（培训先立这三条）：
1. **异议是兴趣的证据**——真想走的客户不提异议，提异议说明他在算这笔账
2. **处理异议的目的=推进决策，不是辩论赢**——把客户说服了但没推进，等于白说
3. **同一句异议，背后是三种不同的真实顾虑**——先拆再答，别背标准答案

## 三段式结构

```
接：共情不断裂（"您这么想很正常"——不是嘴上认同，是让客户把话说完）
拆：找真实顾虑（超预算？怕买亏？家人没同意？砍价习惯？——分支判断）
转：重构+证据+行动（换角度算账 → 给可验证的证据 → 推一小步：带看/二访/算价）
```

## 触发场景
- 客户说出异议原话，需要应对
- 新人培训、异议演练（AI 扮演客户施压）
- 案场统一异议口径（防各顾问答法打架）
- 复盘：把本日/本周真实异议对照本库查处理得失

## 结构

详见 `objections.md`：
- **四大高频异议（第 1 批完整稿）**：太贵了 / 再看看考虑 / 怕烂尾 / 会不会再降价
- **二级异议清单（骨架）**：位置远 / 楼层朝向 / 物业费 / 学区不确定 / 别的盘更便宜 / 家人反对

每条异议五件套：**客户原话 → 顾虑拆解（分支表）→ 应对话术（含可验证证据要求）→ 禁语 → 分客群变通 **

## 合规红线（每条应对输出前必查）

1. **不威胁式施压**："今天不定就涨价/没了"必须有真实调价文件或真实去化数据支撑
2. **不虚假担保**：交付风险类只用证据链说话（监管账户/工程进度/已交付盘），不打包票
3. **数据可验证**：成交价、优惠、库存等证据必须真实可查，宁说"我查一下给您准数"
4. **不贬损竞品**：客户拿竞品压价时，只做客观差异对比
5. **不淡化负债**：月供折算类话术不得引导客户超出偿付能力（"奶茶钱"式话术禁用，改为收入占比健康度算法）

## 与其他技能的关系
- 价格类异议的算账数字一律调用 calc-toolkit（月供/税费/购房成本），不口算
- 逼定动作与时机在 L1-3（本库只处理异议本身，异议化解后何时逼定看 L1-3）
- 客户登记与跟进节奏在 L1-5 判客跟进 SOP
