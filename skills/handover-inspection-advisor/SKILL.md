# 交房验收（handover-inspection-advisor）

## 一句话定位

交房是把"纸上的房子"换成"真实的房子"的那一刻，也是**买方唯一一次有筹码提异议的时点**。
这个技能给的是**一份可打印的验收清单 + 一份可直接递交的问题清单模板**，让人在签字之前把该查的查完、该写的写清楚。

不覆盖：新房交易成本（`newhome.py`）、二手房交易流程与过户（`resale-transaction-sop`）、装修改造方案（不在本库范围）。

## 适用角色

- 购房者本人：自己验、自己提异议（首选，最省钱）
- 置业顾问 / 客服岗：陪同验房时按同一份清单走，避免"客户提出口头问题，公司无法闭环"
- 第三方验房师：把清单当交付模板，结论落到书面
- 房产自媒体 / 顾问：讲清"验房到底验什么"，不做玄学验收

## 八类触发场景

1. 开发商通知交房，客户问"我要带什么、查什么"
2. 客户收房当场发现空鼓、渗漏、门窗关不严，不知道哪些必须整改
3. 实测面积与合同面积不一致，问"补钱还是退钱、能不能退房"
4. 层高、开间尺寸与户型图不符，问"这算不算违约"
5. 开发商要求"先签字再验房"，客户不确定能不能拒绝
6. 验房提了问题，物业只口头答应，一直不整改
7. 已收房，入住后发现渗漏、返味、墙体开裂，问"还能不能找开发商"
8. 二手房交房，需要现场核对清单与欠费

## 五条核心认知

1. **先验后签，顺序不能反**。签字收房在法律上意味着"对交付状态的确认"。允许先验再签的城市与项目越来越多，客户提出这一要求是正当的；合同或通知里写"先签字再验房"的，先谈程序再谈内容。
2. **验收的核心不是"看起来新不新"，是"能不能正常用 + 以后会不会出问题"**。空鼓、渗漏、排水坡向、门窗气密、电路分路——这些出问题时维修成本远高于表面瑕疵。
3. **所有问题必须形成书面清单并留收件证据**。口头反映 + 微信口头答应，等于没有主张。清单要写清位置、现象、依据条款、要求整改的时限。
4. **面积误差是有法定兜底口径的**，不是开发商说了算。先算误差比，再决定"据实结算"还是"主张解除"：

```bash
python3 skills/calc-toolkit/area_error.py --contract {{合同面积}} --final {{产权登记面积}} --price {{合同单价}}
```

5. **收房不是终点，保修期才是真正的保护**。主体结构、防水、管线各有不同的保修期限（按合同与当地规定现查），发现问题的时间点与书面记录，决定你还能不能让开发商负责。

## 必问信息（不齐就先问，别猜）

| 字段 | 为什么要问 |
|---|---|
| 合同约定面积、产权登记（实测）面积、单价 | 决定误差比与补退金额，也决定能不能主张解除 |
| 交付标准：毛坯 / 全装 / 精装（含品牌清单） | 精装房的验收对象完全不同，要有品牌型号对照表 |
| 合同里的交房条件（竣工验收备案、配套完成度） | 判断"是否达到交付条件"，这是拒绝收房的主要依据 |
| 交房通知的表述（是否要求先签字） | 决定现场程序怎么谈 |
| 层高、开间、赠送面积（露台/储藏/夹层）是否写进合同 | 只有写进合同的尺寸才构成交付标准 |
| 保修条款与期限（防水 5 年、主体结构等，按合同现查） | 决定入住后发现问题还能不能主张 |
| 是否有整改承诺书 / 交付标准说明书 | 后续整改的书面依据 |
| 物业费起算时间与预缴方式 | 空置期费用与入住时间的争议点 |

## 知识库与数据来源

- 面积误差与补退：`skills/calc-toolkit/area_error.py`（3% 红线法定兜底口径，含法律依据条目）
- 得房率与套内/建面换算：`skills/calc-toolkit/efficiency.py`（`--mode area` 反推套内，`--mode compare` 比两个盘的套内单价）
- 交房环节的费用核对（维修基金、物业预存、产权登记费）：`skills/calc-toolkit/newhome.py`
- 交房后的持有成本（自住/出租）：`skills/calc-toolkit/holding.py`
- 交付标准与保修期限：**以合同条款与当地现行规定为准，一律现查**；本技能不含任何城市的具体年限数字
- 不可采信：销售口头承诺的"赠送面积""能改"，样板间观感，邻居转述的"开发商不管"

## 目标读者

- **购房者本人**：拿着清单自己验（本技能的第一读者）
- **置业顾问 / 客服**：把客户诉求转成可闭环的工单，避免"客户说什么都先答应"
- **验房师 / 装修公司**：作为交付报告模板，结论必须可复核
- **对外版要删什么**：内部整改成本判断、"这个项目一般不给修"这类内部经验不进客户版

## 写作风格

- 一现象一条目：位置 + 现象 + 判断标准 + 依据，不写"整体感觉不错"
- 只写能复现的：能拍照、能量尺、能放水试验的，才算验收项
- 不夸大：不写"这房子不能收"，写"符合 / 不符合 / 需复测"
- 涉及整改时限与赔偿，一律给区间与依据，不给"必须赔你多少"
- 结论三选一：**可以收房 / 整改后再收 / 存在不能收房的依据（写明依据）**

## 输出格式

- **验收清单（首选交付）**：按 Part 3~4 顺序，逐项打勾（合格 / 不合格 / 需复测），带位置编号
- **问题清单（可直接递交）**：序号 / 位置 / 现象描述 / 参照标准或合同条款 / 要求整改内容 / 要求完成时间 / 附照片编号
- **面积与费用核对表**：合同面积 vs 实测面积、误差比、补退金额、交房应缴费用清单
- **结论页**：三选一结论 + 复验时间建议 + 保留款项建议（如保留 {{金额}} 元尾款或押金）
- 所有交付物必须含：验收日期、参与人员、拍照编号规则

## 数据时间戳

- 面积与尺寸：以产权登记（实测）数据为准，标注测量日期与测量机构
- 保修期限与交付标准：标注合同条款号；政策类（保修最低期限、交付条件）按当地现行规定现查并标注核对日期
- 费用（维修基金、物业费标准）：按交房当期标准，标注文件或公示来源
- 整改承诺：必须写"要求完成日期"，并注明"以书面回复为准，口头无效"

## 与其他技能的关系

- 二手房交易流程、定金、过户 → `resale-transaction-sop`
- 新房交易成本、月供、可贷额度 → `calc-toolkit`（`newhome.py` / `mortgage.py` / `fund.py`）
- 收房后出租的租金与回报 → `owner-rental-advisor` + `rent.py`
- 收房后自住的长期成本 → `holding.py`
- 装修与工程质量深度检测（结构、防水闭水试验的专业判定）→ 专业机构；本技能只给自检项目与判断标准
