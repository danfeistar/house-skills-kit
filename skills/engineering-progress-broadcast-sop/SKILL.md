# 工程进度与品质播报 SOP（标准作业程序）· engineering-progress-broadcast-sop

**一句话**：把工程进度从“拍几张照片发出去”变成有来源、有对照、有边界、有答疑、有归档的透明沟通流程。

**适用角色**：工程部、营销策划、品牌与内容团队、案场负责人、置业顾问、客服和项目负责人。

**触发场景**：
- 月度工程进度播报
- 主体、封顶、外立面、园林、公区等节点更新
- 工地开放日或工法展示
- 业主群、客户咨询中的工程问题答复
- 工期变化、延期风险或质量问题的统一沟通

## 使用规则

1. 工程部书面口径是唯一事实底稿，AI 不根据照片自行推断工期、质量或交付日期。
2. 每个数字、节点、照片和工艺描述都要能回溯到来源、日期和审核人。
3. 区分“已完成、进行中、计划、预计、待确认”，不把计划写成事实。
4. 交付日期、延期、质量投诉等敏感事项只按合同和官方口径答复，不擅自承诺。
5. 播报不是广告包装：重点是让业主和客户看懂进展、知道下一步、知道如何核实。

## 核心流程

```text
工程资料收集 → 现场核验 → 节点对照 → 图文编排
→ 工程/营销/合规审核 → 发布 → 客户答疑
→ 问题登记 → 下期复盘与版本归档
```

## 表述分级

| 状态 | 推荐表达 | 禁止表达 |
|---|---|---|
| 已完成并核验 | “已完成”“已核验” | “品质绝对领先” |
| 正在施工 | “正在施工”“当前进展为” | “马上交付” |
| 计划安排 | “计划”“预计”“拟” | 直接写成确定完成日 |
| 待确认 | “以工程部后续书面口径为准” | AI 自行补齐 |
| 延期或变更 | 如实转述正式口径、影响和后续安排 | 隐瞒、淡化或私下保证 |
| 客户追问质量 | 提供可核验资料和正式答疑渠道 | “肯定没问题”“绝对不会有问题” |

## 客户答疑与问题升级

### 普通问题

1. 先确认客户问的是哪一栋、哪一分项、哪个时间点。
2. 查本期已审核播报和工程资料。
3. 能核实就按资料回答，并标注资料日期。
4. 不能核实就明确说“目前没有可确认口径”，转工程/客服专属通道。

### 敏感问题

涉及延期、结构质量、重大投诉、诉讼、监管、交付责任和赔付的，应立即停止自由发挥：

```text
识别敏感问题 → 截止未经确认的扩展回答
→ 转项目指定负责人 → 使用统一书面口径
→ 记录客户问题与答复版本
```

## 发布前检查

- [ ] 资料来自工程部书面口径
- [ ] 图片拍摄日期、区域和状态可核验
- [ ] 已完成、进行中、计划、待确认没有混写
- [ ] 合同交付日期没有被营销文案改写
- [ ] 规划、品质、工艺、配套没有扩大为保证性承诺
- [ ] 延期或已公开问题没有被删除或模糊化
- [ ] 客户照片、声音、姓名和房号已取得相应用途授权
- [ ] 线上、线下、业主群版本一致
- [ ] 答疑联系人和升级路径已确认
- [ ] 旧版本已归档并停止继续传播

## 合规红线

1. 不得伪造、篡改、截取误导性工程照片或进度数据。
2. 不得把计划、预计、规划、意向写成已经完成或必然兑现。
3. 不得承诺绝对按期交付、绝对无质量问题或未经审批的赔付、优惠和权益。
4. 不得隐瞒已经公开的延期、重大质量问题或正式变更；只能按授权口径说明。
5. 不得擅自公开业主身份、房号、联系方式、肖像和群聊内容。
6. 发现安全隐患、重大事实错误或敏感舆情时，先停止相关发布并升级处理。
