# 接待与需求挖掘 SOP · sales-reception-sop

**一句话**：把客户从进门到离场的首访接待，变成可执行、可复盘、可交接的动作链——接待动线 → 需求挖掘 → 需求确认 → 匹配带看 → 算价/异议/逼定衔接。

**适用角色**：置业顾问（首访执行）、销售主管/经理（接待质检与协助）、案场负责人（流程和客户登记纪律）

**触发场景**：
- 新客户首次到访，需要完整接待
- 客户只说“随便看看”，需求尚未显性化
- 客户需求复杂、家庭成员意见不一致
- 带看前要筛选重点、匹配户型和价值域
- 接待结束，需要把有效信息交给下一位顾问或后续跟进

## 核心认知

1. **接待不是从讲项目开始，而是从判断客户开始**：先让客户说，再决定讲什么。
2. **需求不是问出来的，是在事实、场景和预算之间交叉验证出来的**：客户说“想要大一点”，要继续追问家庭结构、使用场景和可接受总价。
3. **首访目标不是把所有内容讲完**：形成一份可信的客户需求画像，完成一次有效匹配，并留下下一步动作。

## 结构

详见 `reception-playbook.md`：
- **Part 1 接待准备与迎宾**：轮接、来访途径后台核对、渠道/全民/自然/多访辨别、首句开场、自然落座
- **Part 2 首访接待动线**：身份与登记 → 企业品牌 → 大区域规划 → 项目规划与配套 → 户型/样板间 → 其他项目内容 → 算价衔接 → 离场确认
- **Part 3 需求挖掘提问树**：参观过程中的家庭/购房目的/区域交通/居住功能/预算付款/决策人/时间节点七个维度
- **Part 4 客户画像与需求确认**：明需求、隐需求、硬约束、弹性项、未确认项；复述确认防止自说自话
- **Part 5 匹配与带看**：先匹配再讲解；价值域调用、户型选择、带看顺序、客户反馈观察
- **Part 6 团队交接与异常处理**：家庭成员分歧、客户拒答、渠道/老客/重复到访、主管介入、接待记录

每个 Part 的格式：**目标 → 动作 → 示例话术/表单 → 翻车警示 → 【待校准·老何实战位】**

## 合规与纪律

1. 客户身份、联系方式、家庭和财务信息只按案场授权范围登记，不在公开群组传播。
2. 不为客户编造购房资格、贷款额度、学区、规划、价格和库存；不确定就标记“待核实”。
3. 需求挖掘不得诱导客户透露与购房无关的敏感隐私；涉及收入、征信、首付来源，只问与按揭判断直接相关的必要信息，并转 L1-6。
4. 不通过贬低竞品、挑拨家庭关系、制造虚假紧迫感来制造需求。
5. 客户拒绝回答时不强追；记录“未确认”，不得擅自填补。

## 与其他技能的关系

- 价值陈述 → L1-1 案场话术库五域；本技能只判断该调用哪个域，不重复写完整说辞
- 客户异议 → L1-2 异议处理
- 算价与收口 → L1-3 算价与逼定 SOP
- 客户登记、复判、长周期跟进 → L1-5 判客与跟进 SOP
- 贷款资格与材料 → L1-6 按揭问题应对
- 渠道报备归属 → L3 渠道规则与独立③渠道分销线，不能由顾问现场口头改规则

## AI 使用方式

- **陪练**：输入客户画像与到访目的，AI 扮演客户；顾问按提问树接待，AI 检查是否先问后讲、是否漏掉硬约束。
- **画像整理**：输入真实接待笔记，AI 只整理已出现信息；未出现的信息标记“未确认”，不得推断。
- **匹配建议**：输入画像后，AI 输出推荐价值域、带看顺序和待核实问题，不直接虚构项目数据。
- **交接摘要**：按模板输出“已确认/未确认/客户原话/下一步”，供主管或后续顾问接手。
