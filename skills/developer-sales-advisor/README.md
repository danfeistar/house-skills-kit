# 开发商销售顾问 · developer-sales-advisor

站在开发商（甲方）一侧，对**销售结果**负责的技能。与案场执行类技能的分工很清楚：那些技能解决"做得对不对"，本技能解决"卖不卖得动、钱怎么花、什么时候该停"。

## 什么时候用

- 拿盘/接项目前，要判断"能不能接、接了怎么干"
- 开盘前要定价格体系、优惠结构与释放节奏
- 项目去化卡壳，需要找病根、开处方
- 渠道费用越花越多但成交没起来，要算费效
- 要给甲方交周报、月度经营分析、年度推盘计划

## 六个部分

| Part | 内容 | 产出 |
|---|---|---|
| 1 | 拿盘研判与一页纸诊断（12 项必取数据 + 五维体检 + 三档结论） | 一页纸诊断表 |
| 2 | 价格与优惠体系（价差表 + 三层优惠结构 + 释放四段 + 破价防控五条） | 价格与优惠体系表 |
| 3 | 渠道与分销（配比 + 佣金结佣 + 风控四类 + 费效评估） | 渠道配比与费效表 |
| 4 | 去化卡壳五症处方（来访不足/转化不足/结构错配/价格抗性/竞品挤压） | 去化处方单 |
| 5 | 营销预算与投放（费效口径 + 5-3-2 分配 + 素材测试 + 止损） | 预算与投放计划 |
| 6 | 甲方汇报与经营预警（周报 + 六指标 + 三档建议 + 预警红线） | 周报 / 月报 |

## 三条最硬的规则

1. **数据先于判断**：没有前 8 周真实数据的诊断都是猜。
2. **不破价是底线**：明折定锚、暗折做转化、资源置换保价格表，三层比例失控，价格体系一个月内必崩。
3. **处方必须带止损**：多久没效果就停、换成什么，不写清楚等于让甲方无限投入。

## 不自足，也不重复

测算走 [`calc-toolkit`](../calc-toolkit/)（月供、税费、得房率、佣金、提前还款）；案场执行走 `sales-*` 系列；竞品采集走 [`competitive-intel-sop`](../competitive-intel-sop/)；优惠执行走 [`pricing-incentive-release-sop`](../pricing-incentive-release-sop/)；渠道准入与对账走 [`channel-collaboration-sop`](../channel-collaboration-sop/)；C 端购房决策走 [`buyer-first-home-advisor`](../buyer-first-home-advisor/)。

## 合规

不承诺政策、不做虚假宣导、不碰客户隐私、不利诱违规、不越权定价。任何让利都必须有书面审批，任何建议都必须写明风险与止损。

## 什么时候不要用我

这个技能有明确边界，用错场景会得到看似正确但方向相反的结论：

- **拿地前的规划指标与土地经济测算** → 不在本技能范围：需要投前的土地经济与规划模型（本技能从"已有项目"开始）
- **渠道执行层动作（报备、带访、对账）** → `channel-collaboration-sop`（执行层）；渠道政策设计才用 `channel-management-advisor`
- **单个客户的接待、算价、逼定** → `sales-reception-sop` / `sales-closing-sop` / `sales-objection-handling`
- **广告创意与内容生产** → `marketing-materials-sop`（物料）／`property-media-creator`（自媒体内容）
- **价格政策对外说法的合规审核** → `pricing-incentive-release-sop` + 法务；本技能给的是内部决策逻辑

本技能不提供政策数字与法律结论：一律按当地当期公告现查。
