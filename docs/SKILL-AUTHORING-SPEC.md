# 技能编写规范（SKILL-AUTHORING-SPEC）

> 版本：v1（2026-10-27）。适用范围：本仓库 `skills/` 下所有技能。
> 背景：对照 CoWork 技能包（144 个专家定义）实测，我方原有 19 个技能在「必问信息 / 知识库 / 输出格式 / 写作风格 / 目标读者 / 数据时间戳」六段上覆盖率为 0/19，导致技能"有方法论但接不住真实业务输入"。本规范把这六段定为**必备段**。

## 1. 必备结构（12 段）

| # | 段落 | 级别 | 作用 |
|---|---|---|---|
| 1 | 一句话定义 | 必填 | 用一句话说清"这技能帮谁做什么" |
| 2 | 适用角色 | 必填 | 谁该用它（岗位/身份） |
| 3 | 触发场景 | 必填 | 什么情况下会被调用（6 条以上、可判断） |
| 4 | 核心认知 | 必填 | 4 条判断原则，纠正行业常见错法 |
| 5 | **必问信息** | **必填（新增）** | 动笔前必须问清的业务输入，做成表格：必问项 + 为什么 |
| 6 | **知识库与数据来源** | **必填（新增）** | 数据从哪来、哪些必须现查、哪些不许现编 |
| 7 | **目标读者** | **必填（新增）** | 输出面向谁，不同读者关心什么 |
| 8 | **写作风格** | **必填（新增）** | 语言口径（短句/结论先行/禁夸张词等） |
| 9 | **输出格式** | **必填（新增）** | 默认交付几件、每件长什么样 |
| 10 | **数据时间戳** | **必填（新增）** | 数字类交付必须带取数日期与来源 |
| 11 | 正文结构（Part 列表） | 必填 | playbook 的目录，每 Part = 玩法 → 示例 → 翻车警示 |
| 12 | 合规红线 | 必填 | 7 条以上，逐条可判断 |

可选段：与其他技能的关系、培训演练模式、版本说明。

## 2. 文件结构（固定三件）

```
skills/<skill-name>/
├── SKILL.md          # 主文件：frontmatter + 12 段（≤10KB）
├── <topic>-playbook.md  # 正文：Part 1..N（12~20KB），每 Part 三层：玩法 → 示例 → 翻车警示
└── README.md         # 安装者视角：适用谁 / 怎么用（AI 场景 6~8 步）/ 输出纪律
```

## 3. 内容纪律（硬约束）

1. **不编具体数字**：任何城市的价格、税费、限购、学位、贷款利率，一律写"按当地当期公告现查"
2. **测算必走工具**：涉及计算的，调 `skills/calc-toolkit/`，不口算、不给"大概"
3. **示例用占位符**：`{{}}` 形式，要求使用者替换为本案真实数据
4. **每 Part 必须带翻车警示**：只讲正确做法不列错法的 Part 视为未完成
5. **合规红线可判断**：写"不返佣给客户个人"而不是"要合规经营"
6. **不重复兄弟技能**：执行流程归属已有技能的，写引用、不复写（例：渠道决策层引用 `channel-collaboration-sop` 的执行流程）

## 4. frontmatter 规范

```yaml
---
name: <目录名>              # 必须与目录名一致（calc-toolkit 历史例外）
description: <一句话能力 + Use when 触发场景>   # 40~200 字，含中文关键词
license: Apache-2.0
---
```

## 5. 自检

```bash
python3 tools/validate_skills.py            # 硬性：目录名/description 长度/README 存在
python3 tools/validate_skills.py --spec     # 软性：必备 12 段覆盖情况（缺失只提示不报错）
```
